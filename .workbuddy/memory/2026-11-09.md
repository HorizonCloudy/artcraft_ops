### B1 性质修正（重要，别再读成越界修复）
B1 **不是安全洞**。默认策略下 UNC 原生拼写与 `file://host/...` 两种都 fail-closed 拒绝；缺陷只在**显式授权 UNC 读根**时显现：同一资源 `\\server\share\art\x.png` ALLOW、`file://server/share/art/x.png` REJECT。属一致性/可用性缺陷。修法是 RFC 8089 三分支归一（空 authority / localhost → 本地；其它 → UNC；相对形保持），不是加拦截。

### C5：铁律 3 + 帧级信息两者都要
`errors.py:8` 铁律 3「进 logger 的值先 `redact_text()`，只用预格式化参数，禁 f-string / `logger.exception`」。`exc_info=True` 与之等价且 traceback 会把异常 message 里的 64hex 凭证原样打出（云严实测）。但纯 `redact_text(str(exc))` 会丢掉 `to_thread` / `open(` / `fh.read` 三帧区分能力（云雨实测），而那正是 C5 让 flaky 可定位的价值。最终写法：
```
logger.debug("<上下文> (%s): %s", type(exc).__name__, redact_text(traceback.format_exc()))
```
我实测注入含 64hex 的异常后：返回原路径、日志不含 64hex、含 `RuntimeError`、含 `GetLongPathNameW` 栈帧。
⚠️ `redact_text` 是 `errors.py:31-33` 明写的**兜底第二层**，只覆盖 4 类形态，不覆盖任意凭证 ⇒「探测绿」只证明 64hex 被挡住，**不可外推为「日志不泄密」**。变异验证 patch 目标必须是 `artcraft_ops.locator.redact_text`（模块内绑定），patch `errors.redact_text` 会拿到假阴性。

### S10 段判据一致性收紧（13:1x-13:3x，团队 neko-s10-strip）

**立项，且我最初的严重性判断被自己的探针推翻**：我一开始判「真实目录穿越漏洞」，实测后必须改成「判据一致性缺口」。证据（多套 API 一致）：`root/../SECRET` 读到内容；`root/.. /SECRET` 在 Python `open` / .NET `[IO.File]::ReadAllText` / 系统 shell 的 `dir` 三套下全部读不到；对照组 `root/inside.txt `（**普通名**尾随空格）**能**读到 `inside.txt` ⇒ OS 剥尾随空格只对普通名，`..` 必须解析阶段精确匹配。**不主张可利用，不吹严重性。**

**根因（本轮最有价值的一句话）**：`normalize_win_path`（roots.py:74）对**整串**做 `text.strip()`，顺手剥掉**最后一段**的尾随空白 → 精确等于型判据（`seg == ".."`、设备名 `stem`）在**串尾命中、串中落空**。串尾的「严」是整串 strip 的**偶然覆盖**，不是判据在起作用。包含型判据（`":" in seg` ADS、`"~" in seg` 8.3）不受影响，因为它们不看边界。

**缺口规模口径（复核订正，我原来写错）**：抽样 12 格里 5 格不一致，但按 `str.isspace()` 整族计，`..` 与 `con` 各 9 个空白字符是 **18/18 全不一致** —— 是系统性失效，不是零星漏 5 种。**文档不许把 12 格当族大小。**

**修法**（roots.py:136-150，判据 6 行）：`core = seg.strip()`（无参数），后续所有判据改判 `core`；`core` 只用于判定，**返回给调用方的路径保持原样**。全用 core 的三条理由（复核给）：① `":" in seg` ≡ `":" in seg.strip()`，判定等价；② 只改精确型会出现同一段两套拼写；③ 前置跳过 `if core in ("", ".")` 必须用 core，否则 `" . "` 会掉进 stem 判据。**不用 rstrip**：`sequence.py:748` 早已是 `seg.strip()`，只剥右侧会造成新的两层不一致。

**效果（我自己实测）**：12 形态一致性 5/12 → **0/12**；正常路径误杀 0/6 → 0/6；既有应拒放水 0/7 → 0/7。`test_roots.py` 27 → 41 passed；全量 249/1 → **263/1**（+14 = 11 首轮 + 3 空白族，无隐藏连带改动）。
