**真机捞出来的四条缺陷（全是契约错，不是逻辑错）**

1. **PdfCraft 命令目录只出 99 条**。`tools --json` 返回的 `name` 才是 `--script` 唯一认的 tool 名，`command` 只是显示别名。旧解析器按 `command` 取 id，一半条目被去重吃掉。新增 `pdfcraft` 解析器 → 195 条。
2. **旧解析器缓存会继续命中**。`cache_key()` 只有 `app|version|commands_hash`，解析器换了但版本没变 → 直接读回旧落盘结果。加 `parser` 维度。
3. **EffectCraft 全盘失败**。文档记的是 `cmd <json>` 位置参数，实测是 `run --project IN <cmd> <json>`；`--save` 是裸开关，真正落盘用 `--save-as OUT`。`input_mode` 改 `flag_project`。
4. **空参数步骤子进程收到空串**。`cmd_positional` 原来 `if params` 才追加 JSON，EffectCraft 的 `run <id> <json>` json 位必填 → 空步骤现在恒发 `{}`。

**状态机缺陷（真机暴露，我原先没想到）**

用户点取消后，**已完成的任务被改写成 `cancelled`**。`cancel_job` 无条件置 `cancel_requested`，执行循环收尾时 `_finish(CANCELLED)` 覆盖了 `succeeded`/`failed`。改成终态幂等返回；顺带补三处取消检查点（循环头 / spawn 后立刻 terminate / 读流结束后），堵住取消落在 spawn 与读流之间的窗口。真机 `job-c3c532812382` 连取消两次都原样返回 `succeeded`。

**检索**：命令表只有英文，用户说「调亮」命中 0 条。加 15 条常用中文操作词映射；打分从「全串 5 分 + 每词 1 分」改成分级权重（id 4 / label 3 / alias 2 / menu 2），英文按词边界匹配（`brightness` 不再命中 `this`/`nothing` 这类参数说明短词），`params_schema` 移出检索域。

**去标识化**：`_HOME_STOP` 只有全角闭括号，用户后紧跟 `（` 时会吞整句 → 补全角开括号。这是 §19.17（五）留给 S18 的第一条，顺手关掉。

**踩坑（下次省时间）**

- PowerShell 对空哈希表 `ConvertTo-Json` 可能产出空体，宿主侧参数全丢。调宿主接口一律写临时 JSON 文件 + `Invoke-WebRequest -InFile`。
- PowerShell 里别把函数命名成 `H` —— 撞 `Get-History` 别名，`H(...)` 不报错但返回历史记录。
